# chains-web3 L3 决策骨架（蒸馏自智能合约/web3 审计反射；仅限安全验证，判据非利用脚本）
- 场景:目标工作授权门禁|判据:明确 auth.status=granted，目标合约地址/链/资产均在范围内，且有合法授权的源码或已部署地址（区分主网与测试网）；若拟执行仓库脚本，须先披露准确命令及副作用并取得用户单独明确同意|转向:任一缺失仅做被动/只读分析；不得强制或绕过门禁
- 场景:审计面与安全边界|判据:优先读已验证源码或在本地 fork 上做静态与只读分析；主网仅只读 call/查询，默认不发改状态交易、不触碰真实资金；区分已验证源码与仅字节码，标注编译器版本与依赖库版本|转向:仅字节码转 rev；链下后端/签名接口转 web
- 场景:重入与外部调用次序|判据:核对 checks-effects-interactions——状态更新是否先于外部调用/转账，是否有重入锁，是否存在跨函数、跨合约或只读(view)重入，以及 ERC777/ERC721 回调、fallback/receive 入口|转向:确认可重入路径影响资金或账本后证据化提报；多合约串联评估转 pivot
- 场景:访问控制与特权|判据:核对特权函数是否有 owner/role 修饰符且校验正确，initializer 是否防重复调用，是否存在缺失鉴权、以 tx.origin 鉴权、任意可调的敏感 setter、权限转移/多签缺口|转向:先只读确认调用者约束，再评估特权被滥用的影响范围
- 场景:预言机、价格与闪电贷逻辑滥用|判据:判断价格/数量来源能否被单区块或闪电贷资金操纵——是否用即时现价而非 TWAP/多源、是否依赖 balanceOf 或储备即时值、闪电贷能否放大清算/铸币/投票权等业务逻辑|转向:只做数据流与逻辑判定，不在主网构造真实交易；可行性评估限本地 fork
- 场景:整数/取整精度与签名重放|判据:核对取整方向是否恒利于协议、精度损失与除零、unchecked/内联汇编与 0.8 以下版本的溢出边界；签名是否绑定 nonce、chainid、合约地址与 EIP-712 domain，是否防重放与跨链重放，ecrecover 是否校验零地址与 s 值可塑性|转向:签名由链下服务产生时转 web 协同核对
- 场景:可升级代理、存储冲突与 delegatecall|判据:核对代理与实现的 storage layout 是否兼容、有无 __gap 预留、实现合约能否被直接初始化或自毁、delegatecall 目标是否可被控制、函数选择器是否冲突、UUPS/透明代理的升级权限是否受限|转向:升级权限并入访问控制评估；字节码级存储布局核对转 rev
- 场景:Evidence→Finding→Path 与提报|判据:Evidence 记录 ID/来源/SHA-256(源码文件或字节码哈希，无则标 n/a)/复现条件(链、区块高度或 fork 点)与结果；Finding 引证受影响合约与函数、根因与影响、校验状态与置信度及修复建议；Path 连接起点→验证步骤→目标及证据 ID|转向:输出脱敏 bounty/审计报告，移除真实私钥/助记词/凭据，区分候选与已验证，明确未证实项
