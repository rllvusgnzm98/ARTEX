# chains-firmware L3 决策骨架（蒸馏自 firmware-pentest/SKILL.md；仅限安全验证）
- 场景:目标工作授权门禁|判据:明确 auth.status=granted，资产/表面/活动均在范围内，且有合法 network_profile 或明确授权的离线样本；若拟执行仓库脚本，须先披露准确命令及副作用并取得用户单独明确同意|转向:任一缺失仅做被动/只读分析；不得强制或绕过门禁
- 场景:固件样本分诊|判据:记录厂商/型号/硬件修订/SDK/版本/来源/SHA-256，区分官方镜像、OTA 与授权设备样本，确认架构及大小端|转向:样本或型号不符先补证；物理读取、刷写与真实设备测试须单独在授权活动内，不默认执行
- 场景:提取失败或高熵|判据:高熵也可能是压缩，结合头部、签名、分区及文件系统格式核对；binwalk/unblob 结果只是线索|转向:按 squashfs/JFFS2/UBI 格式选择离线分析；证据不足标未知，不推定加密或绕过安全启动
- 场景:组件 CVE 与管理面风险|判据:EMBA/版本命中须核对 backport、构建选项、服务启用状态与输入可达性；硬编码秘密、危险调用须证明实际使用及信任边界|转向:不可达或可达性未证实降为候选；显式 firmware 标签可用 patch_verify 审核已有脱敏证据；单个二进制转 rev，有源码逻辑转 audit
- 场景:仿真失败或行为不同|判据:先排除 NVRAM、设备节点、网卡、架构及大小端差异；仿真成功不证明真机受影响|转向:仅在授权隔离环境做有界无害验证；环境不足退回静态分析，不扫描生产或扩展目标
- 场景:Evidence→Finding→Path 与提报|判据:Evidence 记录 ID/来源/SHA-256/提取偏移/组件路径/复现配置与结果；Finding 引证验证受影响型号、根因和影响；Path 连接样本起点→分析/验证步骤→目标及证据 ID|转向:输出脱敏 CVE/CNVD/bounty 报告、修复与回归建议；秘密只保留脱敏摘要，标明仿真与真机证据边界
