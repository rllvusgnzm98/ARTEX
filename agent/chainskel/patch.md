# chains-patch L3 决策骨架（蒸馏自 patch-diff-exploit/SKILL.md；仅限安全验证）
- 场景:目标工作授权门禁|判据:明确 auth.status=granted，资产/表面/活动均在范围内，且有合法 network_profile 或明确授权的离线样本；若拟执行仓库脚本，须先披露准确命令及副作用并取得用户单独明确同意|转向:任一缺失仅做被动/只读分析；不得强制或绕过门禁
- 场景:CVE/CNVD 或 bounty 补丁前后比较|判据:固定厂商、版本、构建、架构与样本哈希；核对公告和修复提交，区分上游修复与发行版 backport|转向:版本字符串不足以判受影响；先确认实际修复代码及适用配置
- 场景:函数差异是否安全修复|判据:新增边界、整数溢出、锁、引用计数或权限检查须对应可达数据流；排除编译器、优化、重命名与单纯 mitigation 噪声|转向:仅符号迁移转 rev；无因果证据保留假设，不宣称漏洞
- 场景:验证修复有效性|判据:先核对工具版本、依赖、平台及工具在同一哈希样本的预检记录；核对授权隔离样本的同输入 before/after、正常和拒绝对照与环境差异|转向:显式 patch 标签可用 patch_verify 审核已有脱敏证据；不可安全复现则明确未验证，不提供 PoC
- 场景:Evidence→Finding→Path 与提报|判据:Evidence 记录 ID/来源/SHA-256/版本/复现条件与结果；Finding 引用证据验证根因、可达性、影响与修复边界；Path 连接起点→验证步骤→目标及证据 ID|转向:输出脱敏 CVE/CNVD/bounty 报告、修复建议与回归结果，移除密钥/身份/真实地址，明确未证实项
