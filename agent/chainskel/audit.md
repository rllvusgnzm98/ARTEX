# chains-audit L3 决策骨架（蒸馏自 code-audit/SKILL.md；仅限安全验证）
- 场景:目标工作授权门禁|判据:明确 auth.status=granted，资产/表面/活动均在范围内，且有合法 network_profile 或明确授权的离线样本；若拟执行仓库脚本，须先披露准确命令及副作用并取得用户单独明确同意|转向:任一缺失仅做被动/只读分析；不得强制或绕过门禁
- 场景:白盒或 PR 安全审查|判据:固定仓库/commit/目录/服务/语言栈；标出输入、鉴权、租户隔离、支付与密钥的信任边界|转向:无源码转 rev；依赖或流水线问题另列供应链范围，不把普通 audit 日志处理当代码审计
- 场景:SAST 命中分诊|判据:Semgrep/CodeQL/gosec 等命中必须人工核对入口→数据流→危险 API，验证调用可达、配置启用、净化及权限前置条件|转向:不可达或已有有效校验记误报/未验证；不得仅凭扫描器输出提报 CVE/CNVD/bounty
- 场景:注入、鉴权或密码实现疑点|判据:区分参数化与拼接、对象所属校验与仅登录校验、跨租户边界、密钥是否实际使用；同查成功与拒绝路径|转向:在授权本地测试中做最小无害复现及阴性对照，禁止外扩目标或导出真实用户数据
- 场景:修复验证与差分审查|判据:检查修复是否覆盖全部入口、错误路径及同类调用；回归原问题和正常/拒绝用例|转向:仅改危险函数名不足以证明修复；运行时验证超范围则停止并列出所需授权
- 场景:Evidence→Finding→Path 与提报|判据:Evidence 记录 ID/来源/commit/文件哈希/行号/复现条件与结果；Finding 引证验证数据流、根因、影响及 CWE；Path 连接输入起点→调用/验证步骤→安全目标及证据 ID|转向:输出脱敏 CVE/CNVD/bounty 报告、最小复现、修复建议与回归结果，移除代码中的秘密并明确未验证假设
